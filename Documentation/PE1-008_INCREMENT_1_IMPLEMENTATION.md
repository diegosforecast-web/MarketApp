# PE1-008 Increment 1 — Horizon-Calibrated Forecast Intervals

## Implemented scope

This increment replaces trajectory-derived extrema with fail-closed, horizon- and model-version-specific return-residual quantile bounds.

The existing expected forecast remains unchanged:

`forecast_price = current_price × (1 + expected_return)`

Calibration uses:

`residual_return = actual_simple_return - predicted_simple_return`

For a calibrated horizon:

- lower return = expected return + lower residual quantile
- upper return = expected return + upper residual quantile
- lower and upper prices are derived from the current price

The lower and upper values are **calibrated forecast bounds**, not independent predictive models.

## Calibration provenance

The calibration builder does not retrain a temporary estimator and does not use trajectory extrema.

For each supported horizon it:

1. resolves the registered production `return_forecast_hN` model and version from `ModelRegistry`;
2. loads that exact persisted production model bundle;
3. reconstructs the chronological production training cutoff from the bundle's recorded `training_rows` and the reference training CSV;
4. excludes the reference training ticker from calibration evidence;
5. applies the fixed production model, without retraining, to post-training observations from the repository's evaluation ticker cache;
6. splits those observations chronologically into an earlier calibration partition and a later validation partition;
7. estimates the lower and upper residual quantiles from the calibration partition only;
8. reports empirical coverage against the later validation partition only.

This keeps the calibration aligned to the exact production model while avoiding the prior failure mode where a sequence of newly fitted walk-forward estimators was labeled as calibration for production model `v001`.

The default interval uses the 10th and 90th residual quantiles, representing an intended 80% interval. The interval level is a statistical configuration, not a presentation adjustment.

## Artifact metadata

Each horizon record includes:

- horizon;
- model task, version, and model file;
- calibration method and provenance;
- residual definition;
- reference training ticker;
- production training cutoff;
- evaluation tickers;
- lower and upper quantiles;
- lower and upper residual returns;
- calibration sample count;
- validation sample count;
- calibration and validation date ranges;
- intended and empirical coverage;
- return-space interval width;
- calibration MAE, RMSE, mean residual, and residual standard deviation;
- validation MAE, RMSE, mean residual, and residual standard deviation;
- artifact generation timestamp.

## Safety behavior

Production fails closed. Forecast Collection is omitted when calibration is missing, malformed, under-sampled, horizon-mismatched, task-mismatched, model-version-mismatched, generated by an unapproved calibration method, lacks the independent validation partition, or produces invalid price ordering.

The legacy `forecast_price` remains available and unchanged.

No authentication, authorization, entitlement, Stripe, routing, frontend architecture, or expected-price model redesign is included.

## Calibration generation

From the backend directory, generate all five currently registered production horizons in one controlled run:

```powershell
cd C:\Dev\MarketApp\src\MarketApp\backend

python -m backtesting.build_forecast_interval_calibration `
  --reference-csv data\price_history.csv `
  --evaluation-glob "data/market_cache/*.csv" `
  --reference-ticker AAPL `
  --horizons 1 2 3 5 15 `
  --calibration-fraction 0.70 `
  --lower-quantile 0.10 `
  --upper-quantile 0.90 `
  --minimum-calibration-samples 100 `
  --minimum-validation-samples 100 `
  --output calibrations\forecast_intervals.json
```

The builder intentionally excludes AAPL by default because the repository evidence identifies the reference training CSV as AAPL. Do not remove that exclusion unless model-training provenance changes and is separately reviewed.

## Required artifact review before deployment

Review every generated horizon record. At minimum confirm:

- exactly five records exist: `h1`, `h2`, `h3`, `h5`, and `h15` for the currently registered production versions;
- `model_task`, `model_version`, and `model_file` match `models/registry.json`;
- calibration and validation sample counts exceed the configured minimums;
- `calibration_end < validation_start`;
- evaluation tickers do not contain the reference training ticker;
- empirical coverage is reported from the later validation partition;
- lower residual quantile is less than or equal to the upper residual quantile;
- diagnostics contain finite values;
- the resulting price bounds satisfy `lower <= expected <= upper`.

Do not deploy merely because values differ. Unexpectedly poor coverage, implausibly wide intervals, or unstable horizon behavior requires engineering review.
